# EggShip Admin

EggShip Admin is the Persian, RTL administration frontend for EggShip, a B2B wholesale egg-ordering platform. It is an independent TanStack Start application and must remain decoupled from the NestJS backend repository.

## Architecture

- TanStack Start and TanStack Router provide SSR and file-based routing.
- React and TypeScript provide the application layer.
- Tailwind CSS v4 and the local shadcn/base-nova wrappers provide UI primitives.
- Feature code is colocated with its route; shared UI belongs in `src/components`.
- The backend is the source of truth for authentication, authorization, API contracts, cookies, CSRF, and validation.
- The backend-generated OpenAPI JSON is the only source for generated frontend API types; no backend DTOs are handwritten here.

The current repository contains template/demo screens and does not claim to be production-authenticated. Backend integration is intentionally deferred until its OpenAPI contract and deployment topology are reviewed.

## Development

This project uses pnpm and does not require Docker:

```bash
pnpm install
pnpm dev
pnpm build
pnpm lint
pnpm format:check
pnpm typecheck
pnpm test
```

## Localization and RTL

The document defaults to Persian (`fa`) and RTL. New user-facing copy should be Persian, while code, route names, technical documentation, and API types remain English. Prefer logical CSS properties and semantic theme tokens. Jalali dates are not part of this bootstrap.

## Security constraints

- Admin authentication belongs to the NestJS backend.
- Never store access or refresh tokens in localStorage.
- Treat backend HttpOnly cookies as unreadable by browser JavaScript.
- Do not add refresh retries until rotation and concurrency behavior are documented.
- Do not weaken CSRF/CORS or add a BFF/proxy without an approved decision record.
- Do not hardcode production domains or secrets.

## Formatting and line endings

`.gitattributes` declares LF for repository text files and CRLF only for native Windows scripts. Existing files may still contain CRLF because ADMIN-02 does not rewrite the repository wholesale; this is tracked formatting debt. New and changed files should be LF. `pnpm format:check` uses Biome's CI formatter check without modifying files. `pnpm check` remains a broader formatter/linter check and may report legacy drift until files are intentionally renormalized in a dedicated maintenance change.

## OpenAPI workflow

The canonical contract is generated by the independent NestJS backend. The frontend handoff path is `contracts/eggship-backend.openapi.json`, which must remain an exact backend-generated artifact. The contract workflow is documented in `docs/API-CONTRACT.md`. Integration changes should:

1. Copy or export the exact backend-generated JSON into that path and record its backend commit/version.
2. Validate the document before generation; reject missing or malformed input.
3. Generate reviewed TypeScript types with a pinned `openapi-typescript` version into a clearly marked generated directory.
4. Review breaking contract changes separately from handwritten client/runtime changes.

Do not fetch an unrelated specification or manually recreate DTOs.

## Proposed integration boundary

Prefer a same-origin reverse proxy at deployment time. The browser talks to the Admin origin, host-only cookies are scoped to that origin, and the proxy forwards the request cookie and approved CSRF/request headers to NestJS. Preserve `Set-Cookie`, request IDs, status codes, and safe error metadata. TanStack Start server functions may be used for narrowly scoped SSR/server-only operations after the cookie-forwarding and CSRF behavior is verified. A full BFF is not approved by ADMIN-02.
